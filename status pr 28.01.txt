## 0) Overordnet mål og absolutte krav

Vi bygger en internasjonal (ENG) webplattform for krypto-onchain trendanalyse som er abonnementsverdig og behovsstyrt. Primærbrukere er amatører og profesjonelle investorer som er lei av daglige/intradag-prisrapporter. Plattformen skal være pedagogisk (Basic) men også tilby metodisk dybde (Advanced) og eksport i JSON for proffer.

**Absolutte krav:**

* ALDRI prisdata, prisgrafer, prognoser eller rådgivende/imperativt språk.
* Kun deskriptive observasjoner og historisk kontekst.
* Alt må kunne forklares fullt ut (“hva, hvordan beregnet, hvorfor, verdi”).
* Alle datadimensjoner må være eksplisitte: tidsvindu, dekning, freshness/lag, kvalitet/konfidens, enheter/transformasjoner, historisk referanse.
* Chain-spesifikk kontekst er obligatorisk: BTC/ETH/ARB/BASE har ulike metrikker/semantikk og kan ikke tvangsstandardiseres.
* Basic/Advanced forklaringer i UI.
* Notables skal være deskriptive basert på avvik + persistens, ikke råd.

## 2) Pipeline (hva den gjør, på høyt nivå)

Pipeline henter daglige data fra AWS (kjedespesifikt) og produserer “published/v1”-datasett for hver chain (bitcoin/ethereum/arbitrum/base). Pipeline orkestreres via GUI-runner `css_gui_pipeline` som kjører full pipeline når man trykker “kjør pipeline” og populærer `D:\css\main\data\` med nye JSON-er.

Pipeline produserer tre hoved-JSON-formater per chain:

* `gold` = daglige rå/deskriptive metrikker per dato (grunnlaget for all visualisering)
* `derived` = pipeline-deriverte features (bl.a. glidende snitt for mange metrics)
* `meta` = kvalitet/status/freshness/konfidens/regime/scorecards/lag-policy

Den publiserte strukturen vi bruker i web:
`/data/published/v1/<genre>/<chain>/...`
der `<genre>` ∈ {gold, derived, meta}

Viktig praktisk funn: `last365d.json` var tidligere feil (ca 228–245 dager) pga feil logikk/filkilde. Vi verifiserte server vs lokal fil ved å hashe innholdet og telle rader, og fant at “served” og “local” var identiske, men `last365d.json` representerte ikke 365 datapunkter. Etter å fjerne/ flytte backup/-kopi filer og kjøre pipeline på nytt fikk alle chains “pass”.

Vi initierte `web-v1` med Next.js/TS/Tailwind/app-router.

### 3.1 Datahenting i web

Vi har verifisert at `/data/published/v1/gold/<chain>/last365d.json` lastes korrekt.

### 3.2 Chain detail-side: `/chains/[chain]`

Filen: `D:\css\main\web-v1\src\app\chains\[chain]\page.tsx`
Dette er en client-side side (use client) som:

* Leser dataset: `/data/published/v1/dataset.json` for supported chains og windows.
* Leser gold: `/data/published/v1/gold/<chain>/latest.json`
* Leser gold-window: `/data/published/v1/gold/<chain>/last{N}d.json` (prefer 365 om støttet)
* Rendrer en liste av metrikker per chain (chain-aware preferred list + “extras” som fallback)
* Viser Basic/Advanced chain interpretation context (midlertidig hardkodet i page.tsx i denne versjonen)
* Viser “Status” per metrikk (Elevated/Typical/Depressed) basert på 52-ukers baseline av weekly medians:

  * ukentlig median per 7-dagers bucket
  * 52-week distribusjon av weekly medians
  * percentile av siste ukes weekly median
  * “distance vs norm” i IQR-units
* Ingen anbefalinger: status er deskriptiv (“higher than typical relative to the past year”, osv.)

### 3.3 Interaktive grafer med 3 serier (daily + MA7 + MA30)

Ny komponentfil: `D:\css\main\web-v1\src\components\MetricChart.tsx`

* Bruker Recharts.
* Bygger en kontinuerlig dagserie fra rows (fyller manglende datoer med null -> faktisk null? NEI: setter value=null).
* Beregner SMA 7 og SMA 30.
* SMA er “strict”: hvis det finnes null/manglende i vinduet blir MA null (ingen fake smoothing over hull).
* Tooltip på hover viser dato + daily + MA7 + MA30.
* Palette kan settes per chain for “proffe nyanser”.

Chain page.tsx bruker MetricChart per metrikk, med chain-spesifikk palett for MA-linjene.

Recharts må være installert: `npm i recharts`.

### 3.4 Visual theme (globals + layout)

Vi implementerte et mørkt “premium” design-token system i Tailwind globals.

Filer:

* `D:\css\main\web-v1\src\app\layout.tsx`:

  * importerer `./globals.css`
  * bruker `next/font/google` for Inter (var `--font-primary`) + Geist_Mono (var `--font-mono`)
* `D:\css\main\web-v1\src\app\globals.css`:

  * Tailwind directives øverst
  * CSS tokens: background, borders, shadows, gradients, text hierarchy
  * helper-classes: `css-card`, `css-panel`, `css-hero`, `css-label`, `css-mono`
  * inputs styling, focus styling, reduced-motion

Vi hadde en build-feil pga `@import` i globals.css (Tailwind krever @import før @tailwind). Vi fjernet @import helt og gikk over til next/font. Vi måtte også slette `.next` cache for å bli kvitt stale error.

Debug-gating:

* `NEXT_PUBLIC_INTERNAL_DEBUG=1` brukes for å vise/ skjule debug-detaljer i intern build. Prod skal ikke vise debug.
