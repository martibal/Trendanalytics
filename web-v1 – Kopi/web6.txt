Her er en **konkret, patch-orientert kravspec** basert på faktisk kodestruktur i `full.zip` (Next.js App Router). Når dev-teamet er ferdig med punktene under, har dere en nettside som:

1. tydelig kommuniserer **bruks-/nytteverdi** av verdier og grafer (deskriptivt)
2. har en **interaktiv historisk validerings-/tillitsmotor** som lar brukere kvalitetssikre det dere selger fra dag 1

Jeg refererer til **eksisterende filer** som finnes i zippen, og spesifiserer **nøyaktig hva som skal patches**, samt **hvilke nye filer** som må lages.

---

# 0) Overordnet regel (gjelder alle endringer)

All UI-tekst skal være **deskriptiv, ikke normativ**.
Det betyr: “what this shows / commonly used for / supports analysis of” – aldri retorikk som antyder anbefalt handling.

## 3.2 Datagrunnlag: krever meta-historikk (400+ dager)

Per dag trenger dere minimum:

* `date`
* `regime.label`
* `regime.gate.status`
* `confidence.confidence_score` (eller `regime.gate.confidence_score`)
* `regime.drivers` (top 1–3)
* `regime.axes`
* `regime.signals` (for noise filter + integrity)

Dette finnes i deres published meta day-json.

---

## 3.3 Ny API-route for historikk: `/api/regime/history`

Dere er i dag bundet til `export/window` som kun støtter 365 max i klientkode (`AllowedWindow` i `ChainClient.tsx`), og `public/data/published/v1` har day-filer.

**NY FIL**

* `src/app/api/regime/history/route.ts`

**Request**

* `GET /api/regime/history?chain=bitcoin&days=450`

  * `days` default: 450 (eller “all available” med øvre grense)
* evt støtte for `start`/`end`:

  * `GET /api/regime/history?chain=bitcoin&start=2024-01-01&end=2026-02-24`

**Response (komprimert timeline)**
Returner en array med:

```ts
type RegimeHistoryPoint = {
  date: string;
  label: string;
  verdict: "LIKELY_NOISE" | "STRUCTURAL_SHIFT" | "INSUFFICIENT_DATA";
  confidence_score: number | null;
  gate_status: string | null;
  drivers: Array<{ metric: string; axis?: string; band?: string; trend?: string }>;
  axes?: Record<string, { band_high: string; band_low: string; trend: string }>;
};
```

**Hvorfor**

* UI trenger en lett payload for å tegne timeline + stats uten å lese 450 separate filer i browser.
* Day-json kan fortsatt brukes on-demand i `HistoricalInspectorDrawer` for en spesifikk dato.
