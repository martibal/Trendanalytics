# Kravspec: “Regime change vs noise” i web (canonical + custom)

## 0) Målbilde (UX)

Når en bruker åpner:

* **Landing**: Hver chain-card skal gi et *klart verdict* “Likely noise / Structural shift / Insufficient data” + *hvorfor* (kort) + *confidence/gate*.
* **Chain dashboard**: Øverst skal det ligge en “Verdict”-seksjon som oversetter `meta.regime.label` til “Noise vs structural”, viser gate/confidence, og forklarer i Basic/Advanced.
* **Custom thresholds**: Bruker kan slå på “Custom thresholds”, justere terskler, se “Custom verdict” ved siden av “Canonical verdict”, og få “Copy API call” + eksportere config.

---

## 1) Definisjoner (mapping som må implementeres)

### 1.1 Canonical verdict (Noise vs Structural)

Basert på canonical `meta.regime`:

* Hvis `regime.gate.status` er “BLOCKED/DEGRADED/UNKNOWN” (eller confidence under threshold):
  **Verdict = “Insufficient data”**
* Ellers:

  * `label === "STABLE"` → **Verdict = “Likely noise”**
  * `label in {"HEATING","CONGESTED","CHEAP"}` → **Verdict = “Structural shift”**

> NB: Dette er en salgbar oversettelse av regimespråket. Regime-labelen skal fortsatt vises, men sekundært.

### 1.2 “Why” (grunnforklaring)

* Bruk `meta.regime.drivers` (top 1–3) og `meta.regime.axes` (demand/friction/capacity).
* I Advanced-modus vises også `meta.regime.signals` (pct_90d, z_robust, momentum_7d_vs_30d) for metrikkene som er relevante.

## 2) Endringer i eksisterende komponenter (konkret fil-for-fil)

### 2.1 Chain dashboard: legg inn Verdict som primær UI

**Fil som må endres**

* `src/components/chains/ChainDiagnosticHeader.tsx`

**Hva som skal endres**

1. Legg inn en ny seksjon øverst i headeren: `VerdictCard` (ny komponent – se 3.1).
2. Denne skal alltid vise:

   * `Verdict: Likely noise / Structural shift / Insufficient data`
   * `Canonical regime: STABLE/HEATING/CONGESTED/CHEAP`
   * `Confidence score` + `gate.status` + “as-of/lag/coverage” (finnes allerede i headeren; flytt/omprioriter).
3. Legg inn “Why” under verdict:

   * Basic: 1–2 setninger
   * Advanced: en liste med drivers + signalverdier (pct/z/momentum) + axis bands/trend

**Hvorfor**
Dette er stedet brukeren forventer “svaret”. I dag vises labelen, men ikke “støy vs strukturell” eksplisitt.

---

### 2.2 Chain dashboard: integrer custom thresholds i hovedflyten (ikke demo)

**Filer som må endres**

* `src/app/chains/[chain]/ChainClient.tsx`
* `src/components/chains/ChainDiagnosticHeader.tsx`

**Hva som skal endres**

1. `ChainClient.tsx` skal eie state for custom thresholds:

   * `customEnabled: boolean`
   * `customConfig: CustomThresholdConfigV1` (defaults + overrides)
2. Når `customEnabled` er true:

   * kall `/api/regime/custom` (eksisterer) med `{ chain, date: meta.regime.asof_date, config }`
   * vis resultatet i header ved siden av canonical
3. `ChainDiagnosticHeader.tsx` må støtte props:

   * `canonicalMeta: MetaFile`
   * `customResult?: CustomRegimeResult` (fra API)
   * `customEnabled: boolean`
   * callbacks: `onOpenThresholdPanel()`

**Hvorfor**
Dere har allerede custom route + lib, men det er ikke en del av produktets hovedreise.

---

### 2.3 Landing: slutt å vise “snapshot” uten regime/noise verdict

**Filer som må endres**

* `src/components/landing/LandingHero.tsx`
* `src/components/landing/ChainHeroCard.tsx` (NB: denne fila har mye kommentert legacy; bruk den aktive delen)
* (eventuelt) `src/components/landing/ChainSnapshotCard.tsx` dersom den brukes i praksis

**Hva som skal endres**

1. Hver chain-card på landing skal hente **meta latest** (eller meta window) og vise:

   * Verdict (noise/structural/insufficient)
   * Canonical regime label + confidence/gate
   * 1–2 drivers (kort)
   * CTA: “Open dashboard”
2. Fjern/ton ned MA7/MA30 “mental model”-snapshot som primær på landing (det kan være sekundært), fordi det dere selger er regime/noise-konklusjonen.

**Hvorfor**
Landing er “førsteinntrykket”. Hvis den ikke viser *selve produktet* (regime vs noise), ser det ut som en generell chart-side.

---

### 2.4 Chains index (/chains): legg inn verdict i oversikten

**Fil som må endres**

* `src/app/chains/page.tsx`

**Hva**

* For hver chain-kort i oversikten, hent meta “latest” (eller manifest asof + meta file) og vis:

  * Verdict
  * Canonical label
  * Gate/confidence
  * “Last updated” / lag policy

**Hvorfor**
Dette er “directory view”. Den må også selge regime/noise, ikke bare liste lenker.

## 3) Nye komponenter/filer som må lages

### 3.1 Ny komponent: `VerdictCard`

**Ny fil**

* `src/components/regime/VerdictCard.tsx`

**Ansvar**

* Ta inn canonical `meta.regime` (+ optional custom result)
* Render:

  * Stor “Verdict” badge (noise/structural/insufficient)
  * Canonical label badge
  * Custom label badge hvis aktivert
  * Confidence/gate summary
  * Basic/Advanced toggle (bruk `ExplainMode` eksisterende mønster)
  * “What does this mean?” → lenk til methodology/wiki (se 3.4)

**Input props**

```ts
type VerdictCardProps = {
  chain: ChainId;
  canonical: MetaFile;
  custom?: CustomRegimeResult | null;
  customEnabled: boolean;
  explainMode: "basic" | "advanced";
  onToggleExplainMode?: () => void;
  onOpenThresholds?: () => void;
};
```

---

### 3.2 Ny komponent: Threshold panel (UI)

**Ny fil**

* `src/components/thresholds/ThresholdPanel.tsx`

**Ansvar**

* UI for config:

  * Toggle: Enable custom thresholds
  * Inputs (v1): band pct/z + trend eps + gate confidence threshold
  * Presets: Canonical / Stricter / More sensitive
  * Buttons:

    * Reset to canonical
    * Export config JSON
    * Copy API call (curl)
* Persist:

  * localStorage (default)
  * (valgfritt) URL-param (se 3.3)

**Hvorfor**
Dette er “pro-feature” som må være enkel å bruke og lett å kopiere til API.

---

### 3.3 Config state / URL helpers

**Nye filer**

* `src/lib/customThresholds/urlState.ts` (valgfritt men sterkt)
* `src/lib/customThresholds/presets.ts` (anbefalt)

**Ansvar**

* Serialize/deserialize config til URL
* Presets som matcher defaults + typiske overrides

---

### 3.4 “Noise vs Structural” forklaringsside (How-to)

**Ny fil**

* `src/app/how-to/custom-thresholds/page.tsx` (eller oppdater eksisterende hvis den finnes)
* (evt) `src/app/methodology/regime/page.tsx` hvis dere har regime-seksjon

**Innholdskrav**

* Kort forklaring av canonical verdict mapping (STABLE=Noise; HEATING/CONGESTED/CHEAP=Structural)
* Forklaring av terskler (pct/z/eps/gate)
* 3 copy/paste `curl` eksempler mot `/api/regime/custom`
* Link til wiki-termene

**Hvorfor**
Dette er det du sa: en ikke-metodikk-kunde skal kunne lese “how to” og sette opp API-kall med egne terskler.

## 4) Type- og datakontraktendringer i web

### 4.1 Type støtte for signals

**Fil som må endres**

* `src/lib/types.ts`

**Hva**

* Sikre at `MetaFile` inkluderer:

  * `regime.signals` (Record<metric, { axis,current,pct_90d,z_robust,momentum_7d_vs_30d, … }>)
  * `regime.gate` (status/threshold/confidence_score/explanation)
  * `regime.signal_aliases` hvis dere har det i meta (for wiki mapping)

**Hvorfor**
Verdict/Advanced “Why” krever typed access til signals.

---

## 5) API-bruk (web)

### 5.1 Canonical data-kilde

Dere bruker allerede:

* `/api/export/window?chain=...&genre=meta&window=...`
* `/api/export/manifest?...`

**Krav**

* Landing + chains index må bruke canonical meta som sannhetskilde.
* “Latest” kan løses via window=7/30 og ta siste dag i `available_days` eller `meta.updated_through`.

### 5.2 Custom regime API

Dere har allerede:

* `src/app/api/regime/custom/route.ts`

**Krav**

* ChainClient skal bruke denne ruten når customEnabled.
* UI skal vise “effective_config” (valgfritt i Advanced) og reasons.

---

## 6) Akseptansekriterier (QA – dette må devteam teste)

1. **Chain page** viser alltid en stor “Verdict” (noise/structural/insufficient) øverst.
2. Verdict er deterministisk og følger mappingen i 1.1.
3. “Why” viser drivers i Basic (tekst) og signals i Advanced (pct/z/momentum).
4. Når “Custom thresholds” aktiveres:

   * Canonical verdict endrer seg aldri
   * Custom verdict vises ved siden av canonical
   * “Copy API call” genererer fungerende curl mot `/api/regime/custom`
5. Landing (home) viser chain-cards med verdict + canonical label + gate/confidence.
6. `/chains` index viser verdict per chain i listen.
7. Ingen hooks-feil introduseres (ingen betinget rendering som endrer hook-orden).
8. Ingen “await outside async” introduseres.

---

## 7) Implementasjonsrekkefølge (for lav risiko)

1. **VerdictCard** + integrasjon i `ChainDiagnosticHeader.tsx` (kun canonical)

3. Chains index: `/chains/page.tsx` -> vis canonical verdict
4. ThresholdPanel + state i `ChainClient.tsx` (UI-only)
5. Koble ThresholdPanel til `/api/regime/custom` og vis custom verdict
