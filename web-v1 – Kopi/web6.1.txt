
## 0) Absolutte regler (gjelder alle patcher)

**0.1 Descriptive-only**
All tekst i UI skal være “what this shows / commonly used for / supports analysis of”.
Ingen: “you should”, “buy/sell”, “bullish/bearish”, “likely to go up”.

**0.2 No price**
Ingen prisdata, prisgrafer, prisreferanser.

**0.3 Determinisme**

* Samme inputs → samme output.
* Ingen `Math.random()`.
* Hash/identity skal være stabil sortert JSON.

**0.4 Hooks-sikkerhet (fra deres krav)**

* Aldri `await` utenfor `async`.
* Ingen “Rendered more hooks than during previous render” (ingen hooks bak betingelser).

## 2.6 `src/components/trust/NoiseFilterPanel.tsx` (Web6 §3.8)

**Hvorfor:** Demonstrere “noise filtering” ved spike-counting.

**Skal innfri:**

* Dropdown signal keys hentet fra `selectedMeta.regime.signals`

  * driver metrics først, deretter resten
* Spike-mode:

  * `z`: `|z| >= threshold` (default 2.0)
  * `pct`: `pct >= threshold` (default 95)
* Window bakover fra selected date (default 120d)
* Counting:

  * candidates (signal finnes)
  * spikes
  * spikes → noise / shift / insufficient (via history verdict)
  * shares %

**Hvordan (viktig):**

* For å telle spikes historisk må panel ha tilgang til per-day signals for vinduet.
* Derfor: TrustSection skal bygge `metaDayMap[date] = metaDayJson` for vinduet (prefetch med concurrency ≤ 6) og sende den til NoiseFilterPanel.
* Panel må degrade gracefully hvis metaDayMap ikke finnes (vise “spike counting unavailable”).

---

## 2.7 `src/components/trust/ThresholdIntegrityPanel.tsx` (Web6 §3.9)

**Hvorfor:** Bevise mekanisk integritet mellom thresholds og klassifisering.

**Skal innfri (konkret visning):**

1. Canonical:

   * gate threshold (default og brukt)
   * gate pass rate (i valgt vindu eller hele range)
2. Custom:

   * effective threshold config (kompakt)
   * custom verdict/label (for valgt dato)
3. **Signal compliance** på “structural days”:

   * For structural_shift-days: hvor ofte oppfyller N driver-signals terskler (f.eks. pct≥95 eller |z|≥2)
   * Dette er deskriptivt “compliance”, ikke “riktig/feil”.

**Hvordan:**

* Bruk `history points` til å definere hvilke dager som er structural vs noise.
* Bruk `metaDayMap` til å sjekke signals på disse dagene.
* Presenter som counts + shares.
