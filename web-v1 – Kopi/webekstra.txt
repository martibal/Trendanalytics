WEBEKSTRA – REVIDERT STATUS & MÅL
1️⃣ Overordnet formål med WebEkstra-patchen

WebEkstra har ett hovedformål:

Gjøre regime-modellen transparent, kontraktsstyrt og reproduserbar i web/API, uten å endre kanoniske (published) data.

Mer konkret innebærer det:

A) Eksplisitt evidensflate i META

meta.regime.signals skal:

publiseres som del av published dataset

inneholde alle signaler brukt i regime engine

ha:

axis

current

pct_90d

z_robust

momentum_7d_vs_30d

ev. transform + current_raw

være 100% deskriptiv (ingen pris, ingen råd)

Dette gjør modellen:

forklarbar

parameteriserbar

reproduserbar

B) Custom regime API (uten å mutere canonical data)

Endpoint:

POST /api/regime/custom?chain=ethereum

Input:

{
  "config": {
    "gate": { "confidence_threshold": 0.5 },
    "trend": { "eps": 0.2 }
  }
}

Output:

canonical regime (uendret)

effective threshold_config

custom regime label

tydelig skille mellom canonical og custom

Viktig prinsipp:
Canonical published META-filer skal aldri endres av custom config.

C) Kontraktsstyring (contract.json)

data/published/v1/contract.json skal være:

En eksplisitt schema-overflate

Ha:

threshold_config_default

threshold_config_schema

meta.regime.signals definisjon

meta.regime.signal_aliases.defaults_by_profile

identity (canonical vs custom hash)

custom_regime schema

Dette gjør hele systemet:

versjonerbart

dokumenterbart

profesjonelt API-klart

D) Meta rebuild uten full pipeline

WebEkstra krever at man kan:

rebuild meta history

uten å re-kjøre gold/derived

og uten å ødelegge published datasett

Dette er viktig fordi regime-engine er logikk, ikke rådata.

2️⃣ Nøyaktig hva som gjenstår

Dette er en presis sjekkliste over det som fortsatt må fullføres.

🔴 BLOCKER (må være grønn før vi er ferdige)
1) TypeScript må være helt grønn

Kommando:

cd D:\css\main\web-v1
npx tsc --noEmit

Krav:

0 errors

Ingen @ts-expect-error

Ingen prototype-hacks

Ingen any-casts som sprer seg utenfor test

Vitest grønn er ikke nok. tsc må være grønn.

🟡 FUNKSJONELLE KRAV (WebEkstra core)
2) Wrapper for meta-only rebuild (MÅ)

Ny kommando som:

finner earliest gold date automatisk

kjører export_meta_json_history.py

skriver til data/calculated/meta

uten at bruker må angi --start manuelt

Eksempel mål:

python pipeline\tools\rebuild_meta_only.py

Dette er eksplisitt WebEkstra-krav.

3) Meta-only publish (MÅ hvis web leser published)

Mulighet for å publishe kun meta:

Enten:

python publish_artifacts.py --genres meta

Eller wrapper:

python publish_meta_only.py

Skal ikke republish gold/derived.

4) GUI-knapp: “Rebuild META (History)” (MÅ)

I admin/GUI:

knapp

bekreftelsesdialog

progresjonslogg

kjører meta history rebuild

skriver til calculated

(ev. publish meta etterpå)

Dette er eksplisitt i WebEkstra-spesifikasjonen.

5) How-To side for custom thresholds (MÅ)

Ny side:

src/app/how-to/custom-thresholds/page.tsx

Skal inneholde:

Forklaring av canonical vs custom

Parameter-tabell

3 ferdige curl-eksempler

Eksempel respons

Tydelig “Descriptive only”

Dette er kontraktsdokumentasjon mot proffer.
