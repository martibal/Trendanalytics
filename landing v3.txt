## Del 1 — JSON Example Viewer

### 1.1 Plassering på siden

Komponenten plasseres i `JsonLayers.tsx`, under de tre JSON-lag-kortene og over footer-stripen med API-URL-en. Den skal være synlig uten scroll for en bruker som allerede har lest kortene.

```
[Gold kort] [Meta kort] [Derived kort]
[JSON Example Viewer — plasseres her]
[Delivered via GET /api/v1/files/... footer-stripe]
```

### 1.2 Trigger

En enkelt knapp som åpner vieweren. Knappen skal ha samme visuelle vekt som "Full field reference →"-knappen og plasseres til venstre for den øverst i seksjonen.

```tsx
// Knapp-tekst
"View actual published JSON examples →"

// Styling — samme linje som "Full field reference →"
className="inline-flex items-center rounded-full border border-white/10
           bg-white/5 px-4 py-2 text-sm font-medium text-slate-200
           hover:bg-white/10"
```

### 1.3 Modal-struktur

Vieweren implementeres som en CSS-target modal, identisk med det eksisterende `ta-modal`-mønsteret brukt på alle andre sider i produktet.

```tsx
// Modal trigger
<a href="#json-example-modal">View actual published JSON examples →</a>

// Modal wrapper — følger eksakt samme mønster som ExplainModal
<div id="json-example-modal" className="ta-modal fixed inset-0 z-[80]
     items-center justify-center p-4">
```

### 1.4 Intern layout i modalen

Modalen har to nivåer av valg presentert i rekkefølge ovenfra og ned.

**Nivå 1 — Confidence-valg (øverst)**

To tydelige toggle-knapper. Good Confidence er default ved åpning.

```
[ ● Good confidence ]  [ ○ Degraded confidence ]
```

Styling for aktiv/inaktiv:
```tsx
// Aktiv
"rounded-full border border-emerald-500/40 bg-emerald-500/10
 px-4 py-2 text-sm font-medium text-emerald-200"

// Inaktiv
"rounded-full border border-white/10 bg-white/5
 px-4 py-2 text-sm font-medium text-slate-400 hover:text-slate-200"

// Degraded aktiv
"rounded-full border border-amber-500/40 bg-amber-500/10
 px-4 py-2 text-sm font-medium text-amber-200"
```

**Nivå 2 — Fil-valg (under confidence-valget)**

Tre faner: Gold · Meta · Derived. **Meta er default** ved åpning.

```
[ Gold ]  [ ● Meta ]  [ Derived ]
```

**Nivå 3 — Metadata-label (under fanene)**

Én linje som viser nøyaktig hva som vises. Endres automatisk når bruker bytter confidence eller fil.

```
"Actual published data  ·  Ethereum  ·  {dato}"
```

Styling:
```tsx
className="text-xs text-slate-400 border-b border-white/8 pb-3 mb-4"
```

**Nivå 4 — JSON-innholdet**

Scrollbart code-block med syntax highlighting. Maks høyde `max-h-96 overflow-y-auto`.

```tsx
<pre className="rounded-2xl bg-black/40 p-5 text-xs leading-6
                text-slate-200 overflow-x-auto max-h-96 overflow-y-auto">
  <code>{currentExample}</code>
</pre>
```

Begge eksempler bruker **Ethereum** slik at feltstruktur er identisk og brukeren kan sammenligne verdier, ikke skjema.

### 1.6 Forklaringstekst per confidence-nivå

Under metadata-labelen og over JSON-blokken vises én setning som forklarer hva brukeren ser. Endres automatisk med confidence-valget.

```ts
// Good confidence
"This is a normal high-confidence publishing day. All fields are present,
confidence cleared the 0.40 threshold, and the regime engine assigned a
named label with full driver attribution."

// Degraded confidence
"This is a low-confidence day. Several Gold fields returned null from the
source data, pulling data_quality_score below 0.40. The confidence gate
fired and the published label became UNKNOWN/DEGRADED. drivers[] is empty
because the regime engine did not run."
```

Styling:
```tsx
className="rounded-2xl border border-white/8 bg-white/3 px-4 py-3
           text-xs leading-6 text-slate-300 mb-4"
```

### 1.7 Viktig merknad om dataenes autentisitet

**Dataene i eksemplene skal være ekte historiske data hentet fra de faktiske publiserte artifaktene, ikke fabrikerte verdier.**

Utviklingsteamet henter de faktiske JSON-filene for de to datoene fra storage og kopierer verdiene direkte inn i `landing.ts` som statiske konstanter. Datoen i metadata-labelen skal matche de faktiske datoene i dataen.

Dersom det av tekniske årsaker ikke er mulig å bruke ekte data fra akkurat disse datoene, velges to andre datoer som representerer de samme confidence-egenskapene, og disse datoen oppdateres konsekvent i alle referanser.

## Del 2 — History Depth Counter

### 2.1 Datakilde

History depth beregnes server-side ved page render og sendes som prop til `Plans`-komponenten. Den skal reflektere faktisk tilgjengelig historikk i published artifacts — ikke et hardkodet tall.

```tsx
// I page.tsx — server component
const historyDepthDays = await computeHistoryDepthDays();
// Returnerer antall distinct published days på tvers av alle kjeder,
// eller for den kjeden med mest historikk

// Sendes ned til Plans
<Plans historyDepthDays={historyDepthDays} />
```

Fallback dersom beregningen feiler:
```tsx
const historyDepthDays: number | null = await computeHistoryDepthDays()
  .catch(() => null);
// Vises ikke dersom null — ingen fallback-tekst
```

### 2.2 Implementasjon av `computeHistoryDepthDays`

```ts
// src/lib/historyDepth.ts
import { readStorageObject } from "@/lib/storage";
import { readDatasetManifest } from "@/lib/dataset";

export async function computeHistoryDepthDays(): Promise<number | null> {
  const manifest = await readStorageObject(
    "data/published/v1/meta/ethereum/manifest.json"
  );
  if (!manifest) return null;

  try {
    const raw = new TextDecoder().decode(new Uint8Array(manifest.body));
    const json = JSON.parse(raw);
    // manifest.json inneholder liste over tilgjengelige datoer
    const dates: string[] = json.available_dates ?? json.dates ?? [];
    return dates.length > 0 ? dates.length : null;
  } catch {
    return null;
  }
}
```

### 2.3 Visning i Pro-priskortet

History depth vises to steder i `Plans.tsx`:

**Sted 1 — Pro-kortets badge (øverst til høyre i kortet)**

```tsx

"4 chains · 365d · JSON"

// Ny badge når historyDepthDays er tilgjengelig
"4 chains · 365d · JSON"   ← beholdes som entitlement-info

  <div className="mt-3 rounded-xl border border-purple-500/20
                  bg-purple-500/5 px-3 py-2 text-xs text-purple-200">
    History Add-on unlocks{" "}
    <span className="font-semibold text-white">
      {historyDepthDays} days
    </span>{" "}
    of published history — and growing daily.
  </div>

```

**Sted 2 — History Add-on bunnteksten**

```tsx

// Ny — med dynamisk teller
"History Add-on: one-time unlock for the full available history

  : ""

```

## Akseptansekriterier

### JSON Example Viewer
- [ ] Knapp "View actual published JSON examples →" er synlig i JsonLayers-seksjonen
- [ ] Modal åpner ved klikk og lukker ved klikk på backdrop eller ×
- [ ] Good confidence er default ved åpning
- [ ] Meta er default layer ved åpning
- [ ] Bytting mellom Good/Degraded oppdaterer JSON-innhold, dato-label og forklaringstekst
- [ ] Bytting mellom Gold/Meta/Derived oppdaterer JSON-innhold og dato-label
- [ ] Dato i metadata-label matcher faktisk dato i JSON-dataen
- [ ] Teksten "Not fabricated" eller tilsvarende er synlig i modal-headeren
- [ ] Alle seks kombinasjoner viser ekte historiske data
- [ ] Degraded Meta-eksempelet viser `drivers: []`
- [ ] Degraded Gold-eksempelet viser `null`-verdier på manglende felt
- [ ] JSON-blokken er scrollbar ved langt innhold
- [ ] Mobilvisning er brukbar (modal tar full bredde under 768px)

### History Depth Counter
- [ ] `computeHistoryDepthDays()` henter faktisk antall publiserte dager fra manifest
- [ ] Tallet vises i Pro-kortets History Add-on-blokk
- [ ] Tallet vises i History Add-on bunnteksten
- [ ] Dersom `computeHistoryDepthDays()` returnerer `null` vises ingen teller — ingen fallback-tekst
- [ ] Tallet oppdateres automatisk ved ny page render etter hvert som historikken vokser

### Generelt
- [ ] Ingen endringer i layout utenfor JsonLayers-seksjonen og Plans-seksjonen
- [ ] Eksisterende `ta-modal`-mønster brukes konsekvent
- [ ] Ingen nye npm-avhengigheter introduseres
